State of the Art — Autumn 2026: node graphs as text

Published 2026-11-20 · updated 2026-11-20

Most node editors save their graphs in a file only the editor can read. Some write the graph as text and read the same text back: then a change shows as a diff in git, a reviewer can read it, a script or an AI model can write a graph, and a graph can be rebuilt from the file without clicking. This page compares 13 tools on that one question: which way does the graph go between the nodes and the text, and in which format.

Legend

  • Node ⇔ TextBoth ways. The file is the graph: it is saved and loaded back without loss.
  • Node ⇒ JSONThe graph is written out. The file is not read back into the same graph.
  • Node ⇐ PythonCode builds the graph. The graph is not read back as that code.

The word after the arrow is the format: Text, JSON, XML or Python. A note in brackets says what limits it.

How to read it

The arrow says what you can do with the file. With ⇔, you can edit the text, load it, edit the nodes, save, and get text again. With ⇒, the text is a snapshot: edits to it do not come back. With ⇐, the code is the source and the nodes are its output.

Readable git diff says whether a change to the graph shows as a few changed lines. Partial means the file is text but carries generated ids, positions or long XML, or needs a tool to unpack it first. Built from the file says whether the graph can be made from the file by a script or a command, not by hand.

Licence: open source is an OSI licence; commercial may have a free tier, named in the cell. Each row has its sources at the bottom of the page. A cell the sources do not settle says partial.

By family

Blender

Blender, NodeToPython, Geometry Script, Base Node

Blender saves node trees inside the binary .blend file. Its Python API (bpy) can build any tree, but Blender has no text form of a tree that it reads back. NodeToPython goes one way: it writes a tree out as a Python script that builds it again. Geometry Script goes the other way: you write Python and it builds the tree. In both, the Python is not made again from the nodes after you edit them in the editor. Base Node reads and writes the same text in both directions.

Compositing and procedural

Nuke, Houdini, TouchDesigner

Nuke has stored its scripts as text from the start: a .nk file is a list of Tcl-style commands, one block per node with its knobs. It diffs well and renders from the command line. Houdini's .hip is a cpio archive; hexpand and hcollapse unpack and repack it, and hou.Node.asCode() prints Python that recreates a node. TouchDesigner's .toe is binary; toeexpand and toecollapse turn it into readable files and back.

Materials

Substance 3D Designer, MaterialX

Substance Designer's .sbs is XML, and Adobe's Automation Toolkit (pysbs) reads and writes it without the application. MaterialX is an open standard: its .mtlx XML is meant to carry a material graph between applications and renderers. Both are full round trips; the XML is long, so a diff is readable but noisy.

AI image pipelines

ComfyUI

ComfyUI saves a workflow as JSON and loads it back, with node positions and groups. A second JSON, the API format, drops the layout: it is what a script sends to the server to run the graph. Images made with ComfyUI carry their workflow, so dropping one on the canvas loads the graph again.

Game engines

Unity Shader Graph, Godot VisualShader, Unreal Blueprints

Unity Shader Graph assets are JSON files, and Godot saves a VisualShader as a text resource (.tres): both load back and go into git as text, with generated ids in them. Unreal keeps Blueprints in binary .uasset files and offers a diff tool inside the editor; nodes copied to the clipboard become text that pastes back into a graph, but that text is not the saved asset.
